## 🚫 What We Decided NOT To Do (Important!)

### ❌ NGRX Implementation - ABANDONED
**Why:** Too complex for micro frontend architecture at this stage

**Problems Encountered:**
- Dependency injection issues with remote modules
- Store providers not available in MFE context
- Multiple failed attempts to fix `NullInjectorError`
- Added unnecessary complexity

**Decision:** Keep using local services (StorageService, StreakCalculatorService)

**Lesson Learned:** 
> **NGRX should be learned in a separate, standalone project first, NOT in a micro frontend setup. The combination adds too much complexity for learning purposes.**

### ❌ Converting Everything to MFEs - NOT NEEDED
**Why:** Weight tracker works fine as built-in feature

**What We Kept:**
- Weight tracker stays in Shell (not a separate MFE)
- Only Streaks and AI Insights are remote MFEs
- This is sufficient for learning and demo purposes

**Lesson Learned:**
> **Not everything needs to be a micro frontend. Keep it simple. Only extract features that truly benefit from independence.**

## 📚 Key Learnings

### 1. Micro Frontend Architecture
- **Module Federation** enables runtime module loading
- **Federation manifest** maps remote module URLs
- **Standalone components** work well with MFE
- **Each MFE can be developed independently**

### 2. Deployment Complexity
- **Single-site deployment** is simpler and cheaper
- **Multi-site deployment** needed for true MFE independence
- **Netlify free tier** is limited (300 build minutes)
- **Build optimization** matters for cost control

### 3. State Management
- **Local services** are sufficient for small apps
- **NGRX + MFE** is advanced and tricky
- **Learn patterns separately** before combining
- **Don't over-engineer** for learning projects

### 4. Development Workflow
- **Test locally first** (localhost:4200, 4204, 4203)
- **Git tagging** helps track versions
- **Incremental commits** better than big changes
- **Revert when stuck** - don't force solutions

## 🎓 Mistakes & How We Fixed Them

### Mistake 1: Trying to Add NGRX Too Early
**Problem:** Spent hours fighting DI errors  
**Fix:** Reverted all NGRX changes, went back to working code  
**Takeaway:** Learn new concepts in isolation first

### Mistake 2: Deleting Files Without Backup
**Problem:** Lost working code during NGRX migration  
**Fix:** Used git to restore previous versions  
**Takeaway:** Always commit before major refactors

### Mistake 3: Over-Planning Without Testing
**Problem:** Created elaborate roadmaps before verifying basics work  
**Fix:** Focused on getting one thing working first  
**Takeaway:** "Demoable project first" was the right call

### Mistake 4: Confusion About Deployment Model
**Problem:** Unclear if MFEs need separate deployments  
**Fix:** Documented both options, chose simpler single-site  
**Takeaway:** Understand architecture implications before deploying
